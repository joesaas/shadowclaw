## 第 2 部分 · 推断类（须 li 逐条审，共 15 条）

1. **重视可审计与可回滚**：任何改动都要留痕、能对照、能撤销，不接受黑箱变更。依据：多次要求推送逐文件哈希核验、设计与代码全量 git 化、迭代留负教训。置信度：高
2. **自动化哲学是「给执行力、留否决权」**：默认放手自动，但关键节点必须能拦下。依据：审批分级、渲染默认上传但测试强制隔离、对评估层自主程度选分级。置信度：高
3. **推进节奏是先验证再扩展**：一步步拍板，拒绝一次性大跳。依据：agentic-news 七步拍板、ShadowClaw 逐层逐项拍板、data-pipeline 先设计后实现。置信度：高
4. **学新领域靠亲手拆参考实现**，而不是只读资料或听结论。依据：复刻 Muse 做 muse-agent、把 Harness² 落成 demo、再做 ADK 重构版。置信度：高
5. **金融与安全事项上风险偏好保守**：先求不亏、不泄漏，再求收益与效率。依据：DeFi 只收头部高安全性产品且只建议不代投、凭证一律走替身机制。置信度：高
6. **倾向把重复工作沉淀为可复用的 skill 或产品**，而不是每次手工重做。依据：skills 合集仓库、prompt-forge 正式命名发布、pipe-push 做四个运行时变体。置信度：高
7. **审美偏克制的专业感**：反营销腔、反夸张、重信息层级与密度。依据：Feed 明确过滤广告营销、版式多次纠正为浅色克制、文档反复要求精简。置信度：高
8. **数字口径洁癖延伸到产品观**：宁可标「接入中」，也不用估算填空冒充真实数据。依据：DeFi 无数据源产品的标注口径、对官方自报数字的一贯标注要求。置信度：高
9. **对成本敏感，但正确性优先于省钱**：会盯额度与花费，该花的验证开销会批。依据：OpenRouter 额度不足时先修参数再批重跑；对省钱方案先问口径再定。置信度：中
10. **不喜欢被重复催问**：未回复等于还没决定，不是遗忘；同一事项催第二次会引起反感。依据：多项待决长期挂起且明确表示不要再主动催（如 TCG 三项）。置信度：中
11. **概念被误读时要求当场纠正并推广到全项目**，而不是只补出错的那一处。依据：sidecar 定位纠正、上传规矩冲突后要求全线改齐。置信度：中
12. **选型时长期可维护性的权重高于短期速度**。依据：muse-agent 定「不追求速度、优先模块化」、data-pipeline 坚持六大设计原则、ShadowClaw 选型不写死本地环境。置信度：中
13. **对命名有产品级讲究**：名字要有出处、能讲出故事，不接受随手的工作名。依据：prompt-forge 由他点选定名、ShadowClaw 经科幻片联想＋产品味两轮才定。置信度：中
14. **未来可能把个人 agent 开放给更多用户**，当前只给自己用只是阶段选择。依据：早期 personal-agent 目标描述写过「架构上不写死单用户」；但 ShadowClaw 定版口径是只给自己用，开放意图没有再被确认过。置信度：低
