## 第三部分 · 实现与迭代

### 阶段 0 · 冷启动提炼

- 材料方案（2026-10-21 li 确认）：主材料 = 当前 agent（Muse）的运行历史（对话、记忆文件、纠正与决策记录、交付物）——纠正记录即标注数据；辅材料 = li 已交付的技术文档（写法样本）；缺口单列 = 公司内工作材料（Jira、内部排障记录，当前够不到，阶段 2 后补，不以推测填）。
- 已知偏向：这份历史是「li 指挥 agent 干活」的历史，提炼长于标准与验收方式，短于 li 亲手操作的具体动作；缺口靠 li 补注脚与上线后纠正回流补齐。私人事项提炼时筛除，涉及 li 个人的事实进记忆种子须走一次性审。
- 产出：原则定稿（li 审定，标准是「写的是我」）、方法手册 v1（排障先行）、记忆种子清单（事实类与推断类分开，推断类逐条审）。

### 阶段 1 · 执行层最小回路

- 按详细设计实现：单 agent 主循环 + 串行/委派原语 + 编排封装雏形 + 轨迹契约落地。
- 验收：真实排障任务全程轨迹可复盘。

### 阶段 2 · 驾驭层 v1 + 工具接入

- harness/ 目录落地；经 MCP 接入 GitHub、Jira；先开排障场景。
- 验收：处理一次真实排障，步骤与核对动作与手册一致。
- **补注（2026-10-21 li 定）：Jira 暂缓，本阶段只接 GitHub。** 已落地：驾驭层内容正本补齐（memory 种子 41+13 条、guardrails、GitHub 工具卡、排障场景）与代码五模块（loader/assembler/memory/guardrails/conflicts）；GitHub 经 MCP 工厂接入（token 缺失诚实降级，未真实联调），离线验收 demo2 用 FakeGitHub 跑通「场景组装 → 只读工具真调用 → 写操作被护栏 ASK 拦下 → 轨迹带真实 harness 版本号」。

### 阶段 3 · 影子模式试运行

- 真实任务双跑：li 正常做，ShadowClaw 同步做但只对照；记录纠正、实际结果、顺手反馈三类信号。
- 产出：影子报告（吻合度 + 偏差清单，定位到层）+ 回归集 v1。
- 验收：偏差中无原则性错误。
- **补注（2026-10-21）：本轮为历史回放版；真·同步双跑待真实任务。** 已落地：评估层地基（signals 信号存储、regression 回归集加载与程序硬查）、回归集 v1（6 个真实历史排障案例，简报只给症状、参照解带出处）、影子运行器与影子报告 v1（reports/shadow-report-v1.md）。真实回放实跑被 OpenRouter key 上限拦下（组装提示 23,023 tokens > key 提示上限 12,970；另有 402 预留额度问题），0 案例跑完、效果与验收结论未产生——待 li 调高 key 限额或充值后重跑 `shadowclaw shadow` 续完。

### 阶段 4 · 评估层回路

- 信号收集 → 候选改动 → 回归对照（多场景、分项门槛）→ 分级合入 → 迭代报告，转满一轮。
- 验收：合入改动不使任何场景退步；每条改动有证据出处。

### 阶段 5 · 转正与扩展

- 按场景逐个从影子升格分身（先排障，后调研、文档、Jira）；补齐路由、并行、反思原语；接入剩余工具；迁 EC2 并接 Telegram 渠道；主动性最后开、默认关、逐项启用。
- 验收：每场景转正前过影子复检；出问题可退回影子模式。

### 持续运营

- 每周一轮评估迭代（或攒满一批提前跑）；每月记忆审计与成本对账。
- 挂起项（等 li）：工作工具全清单；Jira 实例地址与接入方式。
