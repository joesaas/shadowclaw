# ShadowClaw 项目路线图

> 配套文档：docs/design.md（三层设计定版）。本路线图回答「接下来做什么」：从冷启动到转正共 6 个阶段，每阶段写明目标、产出、验收标准。验收由 li 拍板，不达标不进下一阶段。

## 阶段 0 · 冷启动提炼（先影子，后分身的材料准备）

- **目标**：把「像 li 一样思考」的原料备齐。
- **做什么**：通读 li 的历史工作材料（排障记录、技术文档、Jira 单、与 Muse 的合作记录），提炼三样东西。
- **产出**：原则定稿（六条初稿经 li 审定）；方法手册 v1（排障先行，调研/文档/Jira 跟上）；记忆种子（从既有记录蒸馏的事实、项目、关系）。
- **验收**：li 审定原则与排障手册——标准是「这写的是我」而不是「写得对」。

## 阶段 1 · 执行层最小回路

- **目标**：一条能跑真实任务、轨迹完整的单链路。
- **做什么**：先定 muse-agent 的复用程度（复用/重构/重写）；实现单 agent 主循环 + 串行与委派两种原语 + 结构化轨迹；其余原语（路由、并行、反思）留接口。
- **产出**：可运行的执行层骨架 + 轨迹契约 v1（字段级）。
- **验收**：给一个真实排障任务，全程轨迹可复盘——每步输入、输出、拼装决策都查得到。

## 阶段 2 · 驾驭层 v1 + 工具接入

- **目标**：ShadowClaw 第一次以「li 的方式」干活。
- **做什么**：harness/ 目录落地（原则、手册、记忆、护栏、场景）；接入 GitHub 与 Jira（凭证走替身机制，不落明文）；先开一个场景：工作排障。
- **产出**：驾驭层 v1 + 排障场景配置 + 两个工具连接。
- **验收**：用 ShadowClaw 完整处理一次真实排障，它的步骤顺序和核对动作与手册一致。

## 阶段 3 · 影子模式试运行

- **目标**：只对照、不接管，攒评估层要吃的真实信号。
- **做什么**：一段时期内真实任务双跑——li 正常做，ShadowClaw 同步做但产出只给 li 对照；系统记录三类信号（li 的纠正、任务实际结果、顺手反馈）；偏差按类型归档。
- **产出**：影子报告（吻合度 + 偏差清单，偏差定位到原则/手册/记忆哪一层）；真实任务回归集 v1。
- **验收**：偏差清单里没有「原则性错误」（方法对、细节错可以有；方法错说明阶段 0/2 要返工）。

## 阶段 4 · 评估层回路

- **目标**：自我迭代转起来，且改不坏。
- **做什么**：实现信号收集 → 候选改动提炼 → 回归集对照（多场景混合、分项门槛）→ 分级合入（教训级自动、原则/护栏级 li 批准）→ 迭代报告。
- **产出**：评估层 v1 + 第一轮迭代报告。
- **验收**：完成一轮完整迭代；合入的改动在回归集上不使任何场景退步；报告里每条改动都有证据出处。

## 阶段 5 · 转正与扩展

- **目标**：从影子升格成分身，按场景逐步放行独立交付。
- **做什么**：按场景逐个转正（先排障，后调研、文档、Jira）；补齐其余编排原语（路由、并行、反思）；按 li 的工具清单接入剩余工具；主动性能力（定时巡检、到期提醒）最后开，且默认关、逐项启用。
- **产出**：可独立交付的场景清单（每场景标注转正日期与当时的吻合度）。
- **验收**：每个场景转正前过影子报告复检；转正后出问题可一键退回影子模式。

## 持续运营

- 每周一轮评估迭代（或攒满一批任务提前跑）；每月一次记忆审计（li 抽查长期记忆，删脏数据）；成本按月汇总（模型调用花费对预算）。
- 挂起项（等 li）：工作工具全清单；Jira 的接入凭证与实例地址。
