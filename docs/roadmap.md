## 第一部分 · 三层详细设计（已完成，2026-10-21）

产出物已定版：docs/design-execution.md（执行层）、docs/design-harness.md（驾驭层）、docs/design-evaluation.md（评估层 + 三份层间契约）。以下为当时的范围清单，保留备查。

把每层落到模块级：模块清单、各自职责、对外接口；层间三份契约落到字段级。

- 执行层详细设计：agent 单元结构、五原语实现形态、编排封装（规划者拼装如何落到 ADK）、事实板数据结构、轨迹记录器、预算/超时/恢复、审批挂钩点
- 驾驭层详细设计：六抽屉的文件格式与目录、加载与注入机制、场景装配规则、记忆分级写入的执行流程
- 评估层详细设计：信号采集、回归集管理、改动提炼、对照运行、合入门、迭代报告
- 层间契约：轨迹契约（执行层→评估层）、注入契约（驾驭层→执行层）、改动契约（评估层→驾驭层）
- 产出物：三份模块设计 + 项目目录结构图

## 第二部分 · 技术选型（已定版，2026-10-21）

结论摘要：Python + Google ADK 底座；OpenRouter 为模型主通道；工具 MCP 优先；SQLite 存轨迹与索引；本地先行（adk web UI），后续迁 AWS EC2 接 Telegram；单仓三层分包。全文见 docs/tech-selection.md。

## 第三部分 · 实现与迭代

### 阶段 0 · 冷启动提炼

- 通读 li 历史工作材料，产出：原则定稿（li 审定，标准是「写的是我」）、方法手册 v1（排障先行）、记忆种子。

### 阶段 1 · 执行层最小回路

- 按详细设计实现：单 agent 主循环 + 串行/委派原语 + 编排封装雏形 + 轨迹契约落地。
- 验收：真实排障任务全程轨迹可复盘。

### 阶段 2 · 驾驭层 v1 + 工具接入

- harness/ 目录落地；经 MCP 接入 GitHub、Jira；先开排障场景。
- 验收：处理一次真实排障，步骤与核对动作与手册一致。

### 阶段 3 · 影子模式试运行

- 真实任务双跑：li 正常做，ShadowClaw 同步做但只对照；记录纠正、实际结果、顺手反馈三类信号。
- 产出：影子报告（吻合度 + 偏差清单，定位到层）+ 回归集 v1。
- 验收：偏差中无原则性错误。

### 阶段 4 · 评估层回路

- 信号收集 → 候选改动 → 回归对照（多场景、分项门槛）→ 分级合入 → 迭代报告，转满一轮。
- 验收：合入改动不使任何场景退步；每条改动有证据出处。

### 阶段 5 · 转正与扩展

- 按场景逐个从影子升格分身（先排障，后调研、文档、Jira）；补齐路由、并行、反思原语；接入剩余工具；迁 EC2 并接 Telegram 渠道；主动性最后开、默认关、逐项启用。
- 验收：每场景转正前过影子复检；出问题可退回影子模式。

### 持续运营

- 每周一轮评估迭代（或攒满一批提前跑）；每月记忆审计与成本对账。
- 挂起项（等 li）：工作工具全清单；Jira 实例地址与接入方式。
